# game-save v1.8.0（SaveVault 云端）

镜像：`jun9100/game-save:v1.8.0`（`linux/amd64`、`linux/arm64`）。基于 `v1.7.0`，可以直接升级，也可以回滚到 `v1.7.0`（见下文）。

## 变更

- **网页上管理设备令牌（C3）。** 新增“令牌”页：
  - 列出有效和已吊销的令牌：名称、绑定的设备、在线状态、最近使用时间；还会列出仍在用共享令牌的设备；
  - 直接生成令牌，明文只显示一次，带复制按钮；令牌可以改名、吊销，也可以删除已吊销的记录；
  - **配对**：生成 `ABCD-EFGH` 形式的配对码，带倒计时和二维码。二维码里的服务地址默认是当前访问的地址，可以修改。二维码库放在本地，不依赖外网；
  - **共享令牌兼容期**：在“允许 / 警告 / 停用”三档之间切换。切到“停用”前要二次确认，并列出还在用共享令牌的设备；
  - 设备页显示每台设备用的是设备令牌还是共享令牌；活动列表里有配对、生成令牌、吊销令牌的中文记录。
- **游戏名称与自定义封面（C5 服务端）。**
  - 服务端给每个游戏算出统一的显示名，优先级为：自定义名称、Switch 名称表、客户端上报的名称、游戏 ID。
  - 内置 Switch 名称表（数据日期 2026-11-02，与 Android 内置的同源）。客户端可以通过 `GET /v1/savevault/titles/switch` 下载。
  - 自定义名称和封面可以在设备之间同步。修改带修订号，旧修改不会覆盖新修改。封面只接受 JPEG、PNG，大小不超过 1 MiB。
  - 游戏接口新增 `meta` 字段，旧客户端会忽略它。
  - **这一版还没有**：从 Steam、任天堂抓取封面，以及网页上改名称和封面的入口。这两项会在之后的版本加上。

已有的同步接口、环境变量和错误信息都没有改变。共享令牌的默认档位仍然是“允许”，现有的 PC、Android、Eden 不需要任何改动。

## 数据格式

- 新文件 `savevault-meta.json` 和新目录 `savevault-meta/`，只在第一次设置自定义名称或封面时创建。没用过这些功能，数据目录就和 v1.7.0 完全一样。

## 升级（NAS / 群晖）

1. **记下当前状态**：确认 `GET /healthz` 返回 `ok`；在概览页记下各存档范围的数量。
2. **停掉旧容器**：在 Container Manager 里停止 game-save 项目。
3. **完整备份数据目录**：例如 `cp -a /volume1/docker/game-save/data /volume1/docker/game-save/data-backup-<日期>`。
4. **改镜像标签**：把 compose 里的镜像改成 `jun9100/game-save:v1.8.0`，然后重新构建或启动。
5. **验证**：
   - `GET /healthz` 返回 `ok`，网页左上角的版本号是 `v1.8.0`；
   - 概览中的数量和升级前一致；
   - 侧栏出现“令牌”页；
   - 在维护页运行一次“完整性校验”，结果应为“全部正常”。

## 升级后：把设备换成设备令牌（可选）

1. 在“令牌”页生成配对码。
2. 在每台设备上用配对码连接：
   - 新版 PC 和 Android：在设置里找“用配对码连接”；
   - 旧版客户端和 Eden：在网页上直接生成令牌，粘贴到原来填同步密钥的地方。
3. 等“令牌”页显示没有设备再用共享令牌后，先切到“警告”观察几天，再切到“停用”。

## 回滚

1. 停止 `v1.8.0` 容器。
2. 把镜像标签改回 `jun9100/game-save:v1.7.0` 后启动，直接沿用当前数据目录即可。
3. 回滚的影响：
   - 设备令牌照常可用（v1.7.0 已经支持），只是网页上没有了“令牌”页；
   - v1.7.0 会忽略 `savevault-meta.json` 和 `savevault-meta/`，游戏接口不再返回 `meta`，客户端回到本机的名称和封面。重新升级后，自定义名称和封面原样恢复；
   - 再往前回滚到 v1.6.0 时，见 [`RELEASE_v1.7.0.md`](RELEASE_v1.7.0.md) 的回滚说明：用设备令牌的客户端会全部无法连接。

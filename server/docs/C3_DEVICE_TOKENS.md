# C3：设备令牌与配对

[`SAVEVAULT_CLOUD_PLAN.md`](SAVEVAULT_CLOUD_PLAN.md) 的 C3 阶段。本文是**跨端协议约定**，
Android、PC、Eden 三类客户端都依赖它。约定确认前，服务端不实现客户端会依赖的部分。

## 问题

现在所有同步客户端共用一个 `GAME_SAVE_TOKEN`：

- 丢一台设备，只能给所有设备换令牌、逐台重新填写；
- 服务端无法区分请求来自哪台设备。设备 ID 只是客户端自报的请求头，谁拿到令牌都能冒充任意设备；
- 网页上的“删除设备”只删记录，设备下次请求又会出现。

## 目标与不做的事

目标：

- 每台设备（准确地说是每个客户端安装）一个独立令牌；
- 通过配对码或二维码导入，也可以在网页上直接生成后手动粘贴；
- 网页上可以改名、吊销，吊销立即生效；
- 共享令牌保留兼容期，由管理员手动关闭。

不做的事：

- 不改 Eden 的加密密钥（`save_sync_key`）。设备令牌只替换 `save_sync_token`，所有 Eden 设备仍然共用同一个加密密钥；
- 不做按设备的细粒度权限（只读、只限某个类型）。第一版的设备令牌和共享令牌权限相同；
- 不改 WebDAV 兼容入口，它继续使用独立的用户名和密码；
- 不改管理员认证。

## 令牌

### 格式

```text
gsdt_<令牌 ID>_<密钥>
```

- `gsdt_`：固定前缀，表示 game-save device token；
- 令牌 ID：16 位小写十六进制（8 字节随机数）。它不是秘密，会出现在网页、日志和事件里；
- 密钥：64 位小写十六进制（32 字节，`crypto/rand`）；
- 总长 86 个字符，只含 ASCII 字母、数字和 `_`，可以直接放进 `Authorization: Bearer`，也能粘贴进现有客户端的“同步密钥”输入框。

客户端必须把整个令牌当作不透明字符串，不解析其中的字段。

### 存储

新文件 `device-tokens.json`，和其他状态文件一样原子写入、权限 `0600`。只在第一次生成令牌时创建。

```json
{
  "version": 1,
  "shared_token_mode": "allow",
  "tokens": {
    "3f9c0a1b2d4e5f60": {
      "id": "3f9c0a1b2d4e5f60",
      "name": "客厅的 Android 平板",
      "secret_sha256": "<64 位十六进制>",
      "device_id": "<客户端的设备 ID>",
      "created_at": "2026-11-08T12:00:00Z",
      "created_via": "pairing",
      "last_used_at": "2026-11-08T12:05:00Z",
      "revoked_at": "2026-11-09T08:00:00Z"
    }
  }
}
```

- **只存密钥的 SHA-256**。密钥有 256 位随机熵，不需要加盐或慢哈希；
- 校验时按令牌 ID 找到记录，再对 SHA-256 摘要做常量时间比较。ID 不存在、格式不对、已吊销，一律返回同样的 401；
- 令牌明文只在生成时返回一次，之后服务端无法再给出；
- `created_via`：`pairing`（配对码）或 `admin`（网页直接生成）；
- `last_used_at` 只在会记录设备心跳的请求上更新，每个令牌最多 5 分钟写一次盘。只读请求不写盘，和现有的“读取不算同步”规则一致；
- 吊销后保留记录（`revoked_at` 有值），用于审计。网页上可以删除已吊销的记录；
- 日志和事件里只出现令牌 ID，绝不出现令牌本身或摘要。

### 与设备的绑定

`device_id` 是令牌绑定的客户端设备 ID，规则与现有的 `X-*-Device-ID` 相同（`[A-Za-z0-9._-]`，最长 128）。

- 配对时由客户端在请求体里提供，立即绑定；
- 网页直接生成的令牌，在第一次带有效设备 ID 头的请求时绑定；
- 绑定后，这个令牌的请求一律归到绑定的设备 ID 名下：心跳、上传记录、冲突副本的来源设备都用它。请求头里的设备 ID 与绑定值不同时，忽略请求头里的 ID（记一条警告日志）。设备名、平台、版本仍然取自请求头；
- 所以设备令牌的请求不能冒充别的设备。共享令牌的请求保持现状，仍然信任请求头。

`dashboard.json` 的设备记录新增两个可选字段，用来在网页上显示每台设备是怎么连上来的：

| 字段 | 含义 |
| --- | --- |
| `token_id` | 最近一次请求所用的设备令牌 ID；共享令牌时为空 |
| `auth` | 最近一次请求用的是设备令牌时为 `device`；用共享令牌时为空 |

两个字段都是 `omitempty`。空值就表示共享令牌，所以没用过设备令牌的部署，`dashboard.json` 不会多出任何字段。现有的去重逻辑（30 秒内信息没变就不写盘）要把它们也算进去。

## 配对

### 流程

```text
管理员（网页）                      game-save                       客户端
     │  POST /admin/api/pairings        │                              │
     │ ───────────────────────────────▶ │  生成配对码（只在内存里）      │
     │ ◀─────────────────────────────── │                              │
     │  显示配对码和二维码               │                              │
     │                                  │                              │
     │            用户在客户端输入配对码，或扫描二维码                    │
     │                                  │   POST /v1/pair/claim        │
     │                                  │ ◀─────────────────────────── │
     │                                  │  核对配对码，作废，生成令牌     │
     │                                  │ ───────────────────────────▶ │
     │                                  │   返回令牌（只此一次）         │
     │  网页刷新：配对完成               │                    保存令牌    │
```

### 配对码

- 8 个字符，Crockford Base32（`0-9`、`A-Z` 去掉 `I L O U`），约 40 位熵；显示为 `ABCD-EFGH`；
- 客户端输入时：转大写，去掉空格和 `-`，把 `O` 当作 `0`、`I` 和 `L` 当作 `1`；
- **有效期默认 10 分钟**，创建时可以指定 1–60 分钟；
- **一次性**：成功认领后立即作废；
- 同时最多 5 个未使用的配对码；
- 配对码**只存在内存里**，也只存摘要。服务重启后所有未使用的配对码失效，需要重新生成；
- 认领失败的限流：
  - 每个来源 IP 10 分钟内最多失败 8 次（与管理员登录相同）；
  - 全局 10 分钟内最多失败 30 次，超过后所有认领暂停到窗口结束，返回 429；
  - 40 位的配对码在这个限流下无法在 10 分钟内被暴力猜中。

### 二维码内容

```text
savevault://pair?v=1&server=<URL 编码的服务地址>&code=<配对码>
```

- 服务地址由网页填入，默认是浏览器当前访问的地址，管理员可以修改（比如网页用局域网地址访问，而手机走公网地址）；
- Android 可以注册这个 scheme，用系统相机扫码直接打开 SaveVault；
- PC 端可以接受粘贴这一整串文本；
- 客户端解析后**必须先显示服务地址的主机名，让用户确认**再认领。否则一张伪造的二维码能把客户端引到别人的服务器上，之后的存档都会传过去；
- `server` 只接受 `http` 和 `https`。

## 接口

所有响应都是 JSON。错误响应在现有的 `{"error": "..."}` 之外新增一个可选的 `code` 字段，供客户端分辨原因；旧客户端忽略它即可。

### 客户端接口

| 方法 | 路径 | 认证 | 作用 |
| --- | --- | --- | --- |
| `POST` | `/v1/pair/claim` | 无（配对码本身就是凭据） | 用配对码换设备令牌 |
| `GET` | `/v1/auth/whoami` | 同步令牌（只读） | 查询当前凭据的类型和兼容期状态 |

**`POST /v1/pair/claim`**

请求体（最大 4 KiB）：

```json
{
  "code": "ABCD-EFGH",
  "device_id": "a1b2c3d4-…",
  "device_name": "Pixel 9",
  "platform": "savevault-android",
  "version": "2.6.0"
}
```

- `code`、`device_id` 必填，`device_id` 规则同上；
- `device_name` 是普通 JSON 字符串，可以直接放中文，不需要 RFC 8187 编码。最长 80 个字符，超出截断；
- `device_name` 为空时，用管理员创建配对码时填的名称。

成功（200）：

```json
{
  "token": "gsdt_3f9c0a1b2d4e5f60_…",
  "token_id": "3f9c0a1b2d4e5f60",
  "device_id": "a1b2c3d4-…",
  "name": "客厅的 Android 平板",
  "server_version": "v1.7.0"
}
```

失败：

| 状态 | `code` | 含义 |
| --- | --- | --- |
| 400 | `bad_request` | 请求体格式不对，或缺少必填字段 |
| 401 | `pairing_invalid` | 配对码不存在、已过期或已使用。三种情况不区分 |
| 404 | — | 服务端太旧，或没有配置管理员令牌（配对功能关闭）。客户端提示“服务端不支持配对”，可以继续用共享令牌 |
| 429 | `rate_limited` | 失败次数太多，稍后再试 |

认领成功但响应在网络上丢失时，配对码已经作废，令牌也无法再取回。客户端提示重新配对；网页上那个令牌会显示为“从未使用”，管理员可以吊销。

**`GET /v1/auth/whoami`**

不记录心跳，不写盘。

```json
{
  "auth": "device",
  "token_id": "3f9c0a1b2d4e5f60",
  "device_id": "a1b2c3d4-…",
  "name": "客厅的 Android 平板",
  "shared_token_mode": "warn"
}
```

用共享令牌访问时，`auth` 为 `shared`，没有 `token_id`、`device_id`、`name`。

### 管理接口

都要求管理员登录；写操作还要带 `X-Game-Save-Admin: 1`（与现有管理接口相同）。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/admin/api/device-tokens` | 列出所有令牌（不含密钥和摘要），附带绑定设备的显示名、在线状态、最近使用时间，以及仍在使用共享令牌的设备列表 |
| `POST` | `/admin/api/device-tokens` | `{"name": "…"}`，直接生成一个令牌。响应里的 `token` 只返回这一次 |
| `PATCH` | `/admin/api/device-tokens/{id}` | `{"name": "…"}`，改名 |
| `POST` | `/admin/api/device-tokens/{id}/revoke` | 吊销，立即生效。对已吊销的令牌重复调用返回 204 |
| `DELETE` | `/admin/api/device-tokens/{id}` | 删除记录。只能删已吊销的令牌，否则返回 409 |
| `GET` | `/admin/api/pairings` | 列出未使用的配对码（不含配对码本身）：ID、名称、过期时间 |
| `POST` | `/admin/api/pairings` | `{"name": "…", "ttl_minutes": 10}`，生成配对码。响应：`{"id", "code", "expires_at"}` |
| `DELETE` | `/admin/api/pairings/{id}` | 作废一个未使用的配对码 |
| `PUT` | `/admin/api/auth-settings` | `{"shared_token_mode": "allow" \| "warn" \| "deny"}`，切换兼容期阶段 |

现有接口的调整：

- `DELETE /admin/api/devices/{id}`：删除设备记录时，同时吊销绑定到这台设备的所有令牌，并分别记事件。这样“删除设备”名副其实，设备不会再连上来；
- `GET /admin/api/overview`：设备列表里带上 `token_id`、`auth`，统计里新增“使用共享令牌的设备数”；
- 网页上一台设备的显示名优先级：别名 > 令牌名称 > 设备上报的名称。

### 事件与通知

新增事件类型 `device_paired`、`device_token_created`、`device_token_revoked`。Bark 可以订阅它们（默认仍然只推送冲突）。建议用户把 `device_paired` 加进订阅，有新设备连上来时能立刻知道。

## 认证优先级

服务端按请求的路径分三类处理，彼此不会互相回退：

1. **同步接口**（`/v1/...`，`/v1/pair/claim` 除外）只看 `Authorization: Bearer <值>`：
   - 值以 `gsdt_` 开头：**只**按设备令牌校验。格式不对、不存在、已吊销都返回 401，**不会再拿它去比对共享令牌**；
   - 否则按共享令牌比对，并受兼容期阶段约束（见下一节）；
   - 管理员令牌不是同步令牌：现有的启动检查已经保证它和共享令牌不同，它也不以 `gsdt_` 开头，所以拿它访问同步接口一律 401。
2. **管理接口**（`/admin/...`、`/metrics`）：维持现状，只认会话 Cookie 或 Basic Auth 里的管理员令牌。设备令牌和共享令牌都不行。
3. **WebDAV**（`/savevault/...`）：维持现状，只认独立配置的用户名和密码。

`/v1/pair/claim` 不需要认证；即使请求带了 `Authorization` 头也忽略。

同步接口的 401 响应带 `code`：

| `code` | 含义 | 客户端应该怎么做 |
| --- | --- | --- |
| `token_revoked` | 设备令牌已被吊销 | 停止同步，提示“此设备已被移除，请重新配对”，不要自动重试 |
| `shared_token_disabled` | 兼容期已结束，共享令牌被拒绝 | 提示用户配对 |
| `unauthorized` | 其他所有情况（令牌错误、不存在） | 提示检查令牌 |

`token_revoked` 只在令牌 ID 存在、密钥正确、但已吊销时返回。密钥不对时一律返回 `unauthorized`，不泄露令牌 ID 是否存在。

吊销在下一次请求时生效。已经通过认证、正在传输中的那个请求会正常完成。

## 共享令牌的兼容期

`shared_token_mode` 存在 `device-tokens.json` 里，在网页上切换：

| 阶段 | 共享令牌 | 服务端行为 |
| --- | --- | --- |
| `allow`（默认） | 正常使用 | 不做任何提示 |
| `warn` | 正常使用 | 每个响应带 `X-Game-Save-Auth-Warning: shared-token-deprecated`；`whoami` 返回 `warn` |
| `deny` | 拒绝 | 返回 401，`code` 为 `shared_token_disabled` |

- **不按时间自动切换**。NAS 上的服务由用户手动更新，自动截止可能在用户不知情时把所有设备拒之门外；
- 网页显示还有哪些设备在用共享令牌（`dashboard.json` 里 `auth` 为空的设备），全部迁移后再由管理员切到 `deny`；
- 共享令牌本身不能以 `gsdt_` 开头，否则它会被当成设备令牌而永远无法通过。v1.7.0 启动时检查这一点，碰到就报错退出，提示更换共享令牌；
- `deny` 阶段 `GAME_SAVE_TOKEN` 仍然必须配置。这是为了能回滚到 v1.6.0（它启动时要求这个变量）；
- 管理员令牌没配置时，网页和配对都不可用，也无法生成新令牌，阶段按 `allow` 处理；之前生成的设备令牌仍然有效；
- 之后的版本可能把默认阶段改成 `warn`，但永远不会默认 `deny`。

推荐的迁移顺序：

1. 升级服务端到 v1.7.0，阶段保持 `allow`；
2. 逐台设备配对，或者在网页上生成令牌、粘贴到客户端原来填同步密钥的地方；
3. 网页上确认没有设备再用共享令牌，切到 `warn` 观察几天；
4. 切到 `deny`。

## 升级与回滚

### 从 v1.6.0 升级

- 不需要数据迁移。`device-tokens.json` 在第一次生成令牌时才创建；
- 现有的共享令牌、管理员令牌、WebDAV 凭据都不变，所有客户端照常工作；
- `dashboard.json` 的设备记录只多两个可选字段。

### 回滚到 v1.6.0

- v1.6.0 不认识 `device-tokens.json`，会忽略它，能正常启动；
- **用设备令牌的客户端会全部 401**，直到它们改回共享令牌，或者重新升级；
- 即使之前已经切到 `deny`，v1.6.0 也会重新接受共享令牌。如果当初关闭共享令牌是因为它可能泄露了，回滚前先更换 `GAME_SAVE_TOKEN`；
- v1.6.0 第一次写 `dashboard.json` 时，会丢掉 `token_id`、`auth` 两个字段。重新升级后，设备下一次请求时会重新记上；
- `device-tokens.json` 不受影响。重新升级后，未吊销的令牌恢复可用。

### 备份

`device-tokens.json` 和其他状态文件一起备份即可。里面只有摘要，不含令牌明文；但它决定了哪些设备能连上来，恢复备份等于恢复当时的设备列表（包括当时还没吊销的令牌）。

## 对客户端的要求

### 共同要求

1. **令牌不透明**：设备令牌和共享令牌走同一个 `Authorization: Bearer`，客户端不区分、不解析。现有客户端什么都不改，把网页生成的设备令牌粘贴进“同步密钥”输入框就能用；
2. **配对入口**：设置里增加“用配对码连接”：输入服务地址和配对码（或扫二维码、粘贴 `savevault://pair?...`），先显示服务器主机名让用户确认，再调用 `POST /v1/pair/claim`；
3. **安全保存令牌**：令牌只能拿到一次。用平台提供的加密存储；不写进日志、崩溃报告和导出的诊断信息；
4. **处理 401 的 `code`**：
   - `token_revoked`：停止所有自动同步，提示重新配对，不要重试；
   - `shared_token_disabled`：提示用户配对；
5. **兼容期提示**：看到 `X-Game-Save-Auth-Warning: shared-token-deprecated`，在设置页提示“共享令牌即将停用，请配对本设备”，不要每次同步都弹窗；
6. **状态显示**：设置页可以调用 `GET /v1/auth/whoami`，显示“已用设备令牌连接：<名称>”或“正在使用共享令牌”；
7. **旧服务端**：`/v1/pair/claim` 返回 404 时，提示“服务端不支持配对”，保留共享令牌的填写方式；
8. **设备 ID 不变**：配对时提交的 `device_id` 必须是客户端以后请求时一直使用的那个。配对不应该生成新的设备 ID。

### Android（SaveVault）

- OkHttp 不允许请求头里出现非 ASCII 字符，但令牌只含 ASCII，没有问题；配对请求里的设备名放在 JSON 请求体里，不需要 RFC 8187 编码；
- 令牌的保护不低于现有的同步密钥，建议用 Android Keystore 加密后保存；
- 扫码可选：注册 `savevault://pair` 让系统相机打开 App，或者内置扫码。不能引入依赖 Google Play 服务的扫码库；
- 后台同步（WorkManager）碰到 `token_revoked` 时要停止周期任务，并发一条通知。

### PC（SaveVault，Go + Wails）

- 配对入口：输入配对码，或粘贴整条 `savevault://pair?...`；
- 令牌优先存进系统钥匙串；如果沿用现有配置文件，权限必须是 `0600`；
- 现在只读请求不带设备 ID 头。网页直接生成的令牌，会在第一次带设备 ID 的写入请求时绑定，这不影响使用。

### Eden

- **最小改动为零**：把设备令牌填进现有的 `save_sync_token` 设置就能用；
- **加密密钥不变**：`save_sync_key` 仍然由所有 Eden 设备共用，用来加解密存档。它和设备令牌是两回事，配对不会改动它，用户也不能把设备令牌填到加密密钥里；
- 可选：在设置里加“用配对码连接”，调用 `POST /v1/pair/claim`，把返回的令牌写入 `save_sync_token`；
- 至少要识别 `token_revoked`：停止同步并在界面上提示，不要每次启动游戏都重试。

## 服务端实现要点（约定确认后再做）

- 新文件 `device_tokens.go`：令牌记录、配对码、`clone()`（复制所有 map）、加载和持久化。并发保护沿用“先复制、写盘成功再替换”的模式；
- `tokenAuthorized` 改成返回认证结果（类型、令牌 ID、绑定设备 ID）；`requireToken`、`requireTokenReadOnly` 把结果放进请求上下文，`requestDeviceID` 优先用绑定设备 ID；
- 配对认领的限流用独立的 `loginLimiter` 实例，不和管理员登录共享计数；
- 指标：`game_save_device_tokens{state="active|revoked"}`、`game_save_auth_requests_total{kind="device|shared|rejected"}`；
- 网页部分（令牌列表、配对弹窗、二维码、兼容期开关）等管理网页改版合入后再做。二维码库要放在 `web/` 里本地加载，因为 CSP 只允许 `script-src 'self'`。

必须覆盖的测试：

| 场景 | 预期 |
| --- | --- |
| 配对码认领成功后再用一次 | 401 `pairing_invalid` |
| 配对码过期后认领 | 401 `pairing_invalid` |
| 作废配对码后认领 | 401 `pairing_invalid` |
| 同一 IP 连续失败 8 次 | 第 9 次 429，即使配对码正确 |
| 设备令牌访问同步接口 | 200，记录归到绑定设备 ID，忽略请求头里不同的设备 ID |
| 吊销后用这个令牌 | 401 `token_revoked`；其他设备令牌和共享令牌不受影响 |
| 令牌 ID 正确、密钥错误 | 401 `unauthorized`，不是 `token_revoked` |
| `gsdt_` 开头但格式错误，或令牌 ID 不存在 | 401 `unauthorized`，不回退到共享令牌比对 |
| 共享令牌配置成 `gsdt_` 开头 | 启动失败，错误信息说明原因 |
| 共享令牌在 `allow`、`warn`、`deny` 三个阶段 | 分别为 200、200 加警告头、401 `shared_token_disabled` |
| 管理员令牌当 Bearer 访问同步接口 | 401 |
| 设备令牌、共享令牌访问管理接口（Basic Auth 密码） | 401 |
| 设备令牌访问 WebDAV | 401 |
| 只读接口（`whoami`、状态、列表）用设备令牌 | 不写 `dashboard.json`、不更新 `last_used_at` |
| 删除设备 | 绑定的令牌同时被吊销 |
| 没有配置管理员令牌 | `/v1/pair/claim` 返回 404，共享令牌照常可用 |
| 重启服务 | 令牌仍然有效，未使用的配对码全部失效 |
| 没生成过令牌 | 数据目录里不出现 `device-tokens.json`，`dashboard.json` 里没有新字段 |

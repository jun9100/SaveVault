# game-save v1.7.0（SaveVault 云端）

镜像：`jun9100/game-save:v1.7.0`（`linux/amd64`、`linux/arm64`）。基于 `v1.6.0`，可以直接升级，也可以回滚到 `v1.6.0`（见下文）。

## 变更

- **管理网页改版。**
  - SaveVault 页改成游戏网格：每个游戏一张卡片，显示封面块、游戏名、设备、最近备份、版本数、占用和冲突提示。
  - 范围详情的版本记录改成纵向时间线。
  - 归档文件默认折叠，并按游戏分组。
  - 概览只保留 4 个汇总数字，最近备份改成游戏卡片。
  - 明暗两套主题，手机宽度也能用。
  - 技术信息都保留了，只是降为次要文字或悬停提示：完整快照 ID、归档文件名、SHA-256、设备 ID。
- **设为当前版本（C4）。** 范围页上，可以把任意已存版本设为新的当前版本，冲突副本也可以。必须带上页面看到的当前版本，页面过期时会拒绝（409），不会覆盖别的设备刚上传的版本。
- **清理旧版本（C4）。** 范围页上显示占用，可以手动清理旧版本，并且可以先预览。以下版本永远保留：
  - 当前版本；
  - 所有冲突副本；
  - 冲突副本指向的版本；
  - 最近 N 个普通版本。

  清理只能手动触发，不会自动进行。
- **设备令牌与配对（C3 服务端）。** 每台设备可以有独立令牌，支持配对码、吊销，原来的共享令牌保留兼容期。协议见 [`C3_DEVICE_TOKENS.md`](C3_DEVICE_TOKENS.md)。
  - 这一版只有服务端和管理接口；网页上的令牌列表、配对弹窗和二维码，以及客户端的配对入口，会在之后的版本加上。
  - 共享令牌的模式默认是 `allow`（照常使用），现有的 PC、Android、Eden 不需要任何改动。
- **设备名解码。** 设备名写成 RFC 8187 的 `UTF-8''…` 形式时，服务端会还原成原文。这是为了配合 Android 把中文设备名编码后再发送。
- **概览统计修正。** 30 天图表和“近 7 天上传”现在也会计入 SaveVault 的上传，以前只统计 Eden。

已有的同步接口、环境变量和错误信息都没有改变。

## 升级前检查

- 共享令牌 `GAME_SAVE_TOKEN` **不能以 `gsdt_` 开头**，否则 v1.7.0 会拒绝启动。这个前缀留给了设备令牌。正常生成的令牌不会是这种开头。

## 数据格式

- 新文件 `device-tokens.json` 只会在第一次生成设备令牌时创建。没用过设备令牌，数据目录就和 v1.6.0 完全一样。
- `dashboard.json` 的设备记录可能多出两个可选字段：`token_id`、`auth`。
- SaveVault 的版本记录可能多出可选字段 `promotedAt`。

## 升级（NAS / 群晖）

1. **记下当前状态**：确认 `GET /healthz` 返回 `ok`；在概览页记下各存档范围的数量。
2. **停掉旧容器**：在 Container Manager 里停止 game-save 项目。
3. **完整备份数据目录**：例如 `cp -a /volume1/docker/game-save/data /volume1/docker/game-save/data-backup-<日期>`。
4. **改镜像标签**：把 compose 里的镜像改成 `jun9100/game-save:v1.7.0`，然后重新构建或启动。
5. **验证**：
   - `GET /healthz` 返回 `ok`，网页左上角的版本号是 `v1.7.0`；
   - 概览中的数量和升级前一致；
   - SaveVault 页按游戏显示卡片；
   - 在维护页运行一次“完整性校验”，结果应为“全部正常”。

## 回滚

1. 停止 `v1.7.0` 容器。
2. 把镜像标签改回 `jun9100/game-save:v1.6.0` 后启动，直接沿用当前数据目录即可。
3. 回滚的影响：
   - 已经改用设备令牌的客户端会全部无法连接（401），直到改回共享令牌或者重新升级；
   - v1.6.0 会忽略 `device-tokens.json`，重新升级后未吊销的令牌恢复可用；
   - `dashboard.json` 里的 `token_id`、`auth` 会在 v1.6.0 第一次写入时被丢掉，重新升级后设备下次请求时会重新记上。
